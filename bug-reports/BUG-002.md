# BUG-002: Signup displays confirmation page when registering with an existing email

**Status:** Open  
**Severity:** Medium  
**Priority:** Medium  
**Component:** Authentication / Client-Side Routing  
**Environment:** Localhost (React / Supabase / Vite)  
**Automated Test File:** `tests/authentication.spec.js

---

## 📝 Description

Creating an account via the signup page using an email associated with an existing account displays successful account creation confirmation mesage instead of displaying an error on the sign up page. Users may not know if the email entered is already in use since there is no message or confirmation that an account with that email already exists.

While this does not break the authentication or the account creation functionality, it can be misleading and confusing for users leading to poor user experience.

_Note: Using an existing email for sign up does not result in any email being sent to the existing user. It also does not modify any of the user row data of the Supabase backend._

---

## 🔄 Steps to Reproduce (Automated)

1. Open the Playwright test suite in UI mode using `npx playwright test tests/authentication.spec.js --ui`.
2. Run the test: `Signup with an existing email displays an appropriate error and does not show the confirmation page`
3. Observe how signing up using the existing test credentials renders the confirm email page with no error message about the email already being in use.

### Steps to Reproduce (Manual Emulation)

1. Open the application's sign up page at `http://localhost:5173/signup`.
2. Enter `Noto QA` for name, `mcavada97@gmail.com` for email, `password123` for both password fields.
3. Click "Sign up" button
4. Observe the signup confirmation page with the text:
   > "We sent a confirmation link to `mcavada97@gmail.com`. Click it to activate your account."

---

## 🛑 Expected vs. Actual Result

### Expected Result

Clicking on the sign up button when using an existing email to create a new account shows an error message in red text "An account associated with that email already exists." above the sign up button.

### Actual Result

The signup page rerenders with the confirmation message: "We sent a confirmation link to `mcavada97@gmail.com`. Click it to activate your account." No email is sent to the existing user. API response code is 200 with no issues.
