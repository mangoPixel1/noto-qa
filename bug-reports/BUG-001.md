# BUG-001: Race Condition Allows Logged-Out User to Access Authenticated `/dashboard` Route

**Status:** Open  
**Severity:** High (Security Boundary Violation)  
**Priority:** High  
**Component:** Authentication / Client-Side Routing  
**Environment:** Localhost (React / Supabase / Vite)  
**Automated Test File:** `tests/authentication.spec.js

---

## 📝 Description

A race condition exists in the logout flow. When clicking the "Sign out" button, the client-side router immediately changes the URL to the homepage (`/`), but the application fails to completely clear the session state or wait for Supabase's async token destruction to resolve before updating the view.

Because execution speed in automated environments (Playwright) bypasses human delays, the script can force-navigate straight back to `/dashboard` immediately after logout and gain full access to private components.

_Note: This issue is visually masked during manual QA due to human typing/clicking delays, but represents a valid public-terminal session leak vulnerability._

---

## 🔄 Steps to Reproduce (Automated)

1. Execute the automated test suite via Playwright using `npx playwright test`.
2. Observe the execution on the `Security check: Logged out user cannot access authenticated routes` test block.

### Steps to Reproduce (Manual Emulation)

1. Log into the application at `http://localhost:5173/login`.
2. Click the **Sign out** button on the sidebar.
3. _Within 50 milliseconds_ of redirection, forcefully navigate the browser back to `http://localhost:5173/dashboard`.

---

## 🛑 Expected vs. Actual Result

### Expected Result

Upon hitting the logout action, session tokens are completely destroyed before routing changes. Any immediate attempt to access `/dashboard` or other private routes should result in a hard redirect back to `http://localhost:5173/login`.

### Actual Result

The browser URL changes to `http://localhost:5173/`, but the underlying dashboard DOM remains available. The app accepts the immediate incoming request to `/dashboard` because the state validation lags behind the routing mechanism.
